Findings:
- The MuJoCo viewer must run out of process (`rtloop/viewer_proc.py`, shared-memory seqlock + MJB handoff per reset):
  in process it cost 7-10 ms per tick.
- With the viewer, HUD and x11grab recording on the same 5090, WBC GPU compute rises 0.17 → 0.27 ms p50 and the
  transport/wake-up overhead 0.44 → 0.72 ms p50 (T-1.10 without them vs t14c).
- A plain busy-poll starves zmq's I/O thread, which `--cpus 4` pins to the same core (50 Hz bench, overhead p99:
  blocking 1.49 ms, spin 0.92 ms, spin + yield 0.37 ms). `rtserve/wbc_gpu_server.py` now yields on every miss, and
  `demo.sh` / `jobs/_common.sh` start the WBC server with `--spin` by default (`--no-wbc-spin` / `T2_WBC_SPIN=0`).
- Background work must avoid the RT cores and their SMT siblings (2/18, 3/19, 4/20, 6/22, 7/23, 12-15/28-31).

The run overlapped S1 (TT device) and CPU test lanes; its timing is not gated by T-1.10 (period max 232 ms, 86 slips,

the 63 MB. Fixed in `rtloop/telemetry.py` (extras dropped once a row is two episode ends old; a write watermark

re-measured in T-2.8 (2 h, same rt_sim code, TT VLA): +25.7 MB (anonymous +21.6 MB), 236 episodes, under the 50 MB gate.
