## Findings

- MK's `ttnn` is a symlink into the live tt-metal clone, so without `TT_METAL_RUNTIME_ROOT` the device compiles the
  live tree's kernels (the first cold build failed on the live Stage-3 `dit_kernel.cpp`). `rttt/g1_n16.pin_runtime_root()`
  and `env.sh`'s `ttpy` pin it to MK. Any MK device result after 2026-09-19 without the pin is suspect;
  `publish/worktree-mk-env.sh` should export it too (outside RT, the user's file).
- GPU contention: T-2.3 measured while `:5565` served the M1 campaign had RTT p99 52.8 ms; idle, 45.5 ms.
- `server_g1` runs under `taskset -c 8-11` with one-thread BLAS pools (otherwise numpy's pool threads start with the
  caller's CPU mask).
- The x11grab recorder ignored the first SIGINT, so `demo.sh`'s 10 s grace ended in SIGKILL and every recording up to
  T-2.6 lacks its moov atom. Fixed: fragmented MP4 and INT, then TERM.
